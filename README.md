# NexaStream operator dashboard

This **separate private-operator console** manages customer MAC addresses, expiry, activation/suspension, and replacement links on the already hosted TV API at `https://nexastream-tv.onrender.com`. It is not an IPTV player and does not host videos. Your existing dark admin UI is included. Customer data remains in the TV service's PostgreSQL database, not here.

## Deploy

In Render, choose **New → Blueprint**, connect `krishhathidara/iptv-Dashboard`, and review `render.yaml`. The TV service must already exist as `nexastream-tv` in the **same Render workspace**. The Blueprint now references that service's `ADMIN_API_KEY` for `TV_ADMIN_API_KEY` and its `RENDER_EXTERNAL_URL` for `TV_API_URL`; no key needs to be entered in the dashboard or copied to GitHub. During setup supply the one **secret** requested by the Blueprint:

1. `DASHBOARD_PASSWORD`: generate a random secret at least 32 characters long. This is what you type into the dashboard Sign in form; **do not enter the TV API key in that form**. Save the password in a password manager.

For an **existing** dashboard service, sync the updated Blueprint and confirm its `TV_ADMIN_API_KEY` is referencing the TV service's `ADMIN_API_KEY` and `TV_API_URL` points at the TV service. Render updates cross-service references on Blueprint sync, not immediately when the TV key changes. A dashboard created manually (not from this Blueprint) needs its Render environment updated instead. Do not remove the TV service's key: the public TV service refuses customer writes without it.

`DASHBOARD_SESSION_SECRET` is generated by Render. Render sets `RENDER_EXTERNAL_URL` for the new dashboard service, which the app uses for request-origin checks. If you use a custom domain, set `DASHBOARD_PUBLIC_URL` to its exact HTTPS origin in the dashboard service's Environment before signing in. Do not deploy this app as GitHub Pages, a static site, or on plain HTTP. Verify the deployment's `/health` endpoint returns `{"status":"ok"}` and open the **actual dashboard URL** from Render; pushing to GitHub alone does not create that URL. The TV service must remain live and reachable. This dashboard only permits same-origin cookie/CSRF protected customer actions; it does **not** accept your TV admin key in browser requests. Use HTTPS and protect your operator password. It has basic per-instance failed-login throttling, not enterprise authentication/MFA; use additional access control for production.

### If customers do not load

Sign in with the dashboard service's `DASHBOARD_PASSWORD`, **not** either API key. Sign in reports whether authentication worked separately from the TV customer connection. The New Customer and My Customers sections open after authentication even if the initial TV request fails; the message beside Create shows why saving is currently blocked. Use **Refresh** once the TV service is working. Customer creation and updates still require the TV service; never repeat a timed-out create before refreshing the list, because it may already have succeeded. A red **“TV service rejected the admin key”** message means your operator password *did* sign in, but the server-to-server `TV_ADMIN_API_KEY` does not match the TV service's `ADMIN_API_KEY`; entering that key in the password form cannot fix it.

In Render, check **both** services separately: the dashboard service Environment needs `TV_API_URL` set to the **actual** TV service HTTPS origin (no path), `TV_ADMIN_API_KEY` referencing the TV service's `ADMIN_API_KEY` (or manually matching it if the dashboard was not created by the Blueprint), and `DASHBOARD_PASSWORD` set to a separate 32+ character secret. Save environment changes and wait for redeployment. On the TV service, check **Logs** for errors from `/admin/subscribers`, its PostgreSQL database is available, and its `/health` endpoint responds. The TV health response alone does not check the customer database. If you see a key rejection, fix the key pair privately; if a timeout, wait for the sleeping service to wake and use Refresh; if a server error, inspect the TV service logs and database status. Never put real secrets in a support message or GitHub. Rotate any previously shared keys/passwords in Render before using real accounts.

## Create a customer and enter the portal URL on a TV

Sign in with `DASHBOARD_PASSWORD`. Enter the customer's name, the **MAG device MAC address** (six hexadecimal pairs, e.g. `AA:BB:CC:DD:EE:FF`), and duration. **Activate immediately** is checked by default; uncheck it if you want to activate the account later from My Customers. The dashboard shows **“Account created for …”** beside the Create button only after the TV service confirms the save, along with the new links. **Copy the `MAG external portal URL` shown at creation**; the three generated links cannot be fetched again later, but you can choose **Replace URLs** to issue new links (immediately invalidates old portal/playlist links). On a compatible MAG box, use **System settings → Servers → Portals → Portal URL** and enter the full customer-specific address displayed in the dashboard, shaped like:

```text
https://nexastream-tv.onrender.com/stalker/<unique-private-token>/c/index.html
```

`<unique-private-token>` is **not a literal value**; the website homepage and dashboard URL are **not** MAG portal URLs. The TV service checks that the account is active, unexpired, and that the MAC *reported by the device* matches the saved MAC during the MAG handshake. The URL itself is also private: knowing the MAC alone does not make the homepage work on a MAG box. The `TV browser URL` (`/watch/<token>`) is for TV web browsers; the `.m3u` link is for M3U-compatible players. Third-party Stalker apps or individual MAG firmware may not support this limited external portal, so test on your physical box. The TV catalog starts empty unless you import authorized streams into the TV service separately; this dashboard currently manages **customers**, not channels.

Suspending an account stops future portal/API/playlist requests, not an upstream stream URL the TV has already received. A reported MAC can be spoofed; do not assume this identifies hardware. Only use video streams you are licensed to distribute. The TV host's free Render database expires after 30 days unless upgraded; free web services sleep when idle, which can disrupt TV access. Do not use free trial resources for paying customers.

## Local checks

Install dependencies in a virtual environment and run `python -m pytest -q` and (with Node.js available) `node --test tests/dashboard_ui.test.js`. For local use set the values from `.env.example` in your shell environment; the app intentionally fails startup without a TV key and session secret. **Only for private loopback testing:** set `DASHBOARD_PASSWORDLESS_LOCAL=true`, `DASHBOARD_PUBLIC_URL=http://127.0.0.1:8000`, leave `DASHBOARD_PASSWORD` unset, and run the dashboard bound to `127.0.0.1` (`python -m uvicorn main:app --host 127.0.0.1 --port 8000`). The sign-in form is hidden and the local browser gets a session automatically. The TV key is still required server-side and `TV_API_URL` must be the actual HTTPS TV service origin; this mode is blocked on Render and non-loopback hosts. Never commit real secrets.
